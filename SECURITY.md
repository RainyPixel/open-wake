# Security policy

Only the latest release receives security fixes while the project is in the
0.x series.

Please report vulnerabilities through the repository's private GitHub security
advisory flow (`Security` → `Report a vulnerability`). Do not open a public
issue containing exploit details, credentials, or private logs.

Reports should identify the affected version, platform, trust boundary, and a
minimal reproduction. Relevant boundaries include hook configuration merging,
predicate process isolation, condition-file ownership, release checksum
verification, and executable replacement.
