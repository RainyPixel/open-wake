# Releasing

Release Please is the only release authority. It reads Conventional Commits on
`main`, maintains one release pull request, and updates `Cargo.toml`,
`Cargo.lock`, `CHANGELOG.md`, the pinned README example, and
`.release-please-manifest.json` together.

## Normal release

1. Merge conventional commits into `main`. Use `fix:` for a patch, `feat:` for
   a minor, and `!` or a `BREAKING CHANGE` footer for a major release.
2. Review the release pull request generated by
   `.github/workflows/release-please.yml`.
3. Confirm its CI run and version/changelog diff, then merge it.
4. Release Please creates a draft GitHub Release. The same workflow tests and
   builds all four native archives, uploads one `SHA256SUMS`, and publishes the
   draft only after every build succeeds.
5. Read back the published release, assets, checksums, and installed binary
   version before declaring release closure.

Do not edit package versions, the manifest, release tags, or changelog entries
by hand, and do not run `cog bump`. Cocogitto validates commit history only.

The workflow uses `GITHUB_TOKEN`. GitHub suppresses ordinary workflow events
created by that token, so the release workflow explicitly dispatches CI for
generated release PRs and performs artifact publication in the same run.

If a native build or upload fails, the release remains a draft. Rerun the
failed workflow jobs; uploads use `--clobber`, so a successful rerun repairs the
draft before publication.

## Release assets

The native matrix is:

- x86_64 Linux (static musl)
- aarch64 Linux (static musl)
- x86_64 macOS
- aarch64 macOS

Asset names are a public installer and updater contract:

```text
open-wake-x86_64-unknown-linux-musl.tar.gz
open-wake-aarch64-unknown-linux-musl.tar.gz
open-wake-x86_64-apple-darwin.tar.gz
open-wake-aarch64-apple-darwin.tar.gz
SHA256SUMS
```

Do not rename these without updating both `install.sh` and `src/update.rs`.
